# Проверки

- dq_checks.sql:65 проверок PASS/WARN/FAIL. MODEL вызывает FAIL/откат; SOURCE и SNAPSHOT дают WARN. На исходном снимке56 PASS,9 SOURCE WARN.
- verify_answers.py:56 проверок реального вывода Q1–Q10,11 CSV. Инварианты текущих данных всегда строгие; старые контрольные числа предупреждают только при изменённом raw.
- raw_baseline.csv:неизменяемый эталон исходного raw. compare_raw_baseline.py печатает различия таблиц, не обновляет эталон.
- raw_fingerprint.sql:хеши raw payload без технического _loaded_at; сравнение до/после сборки строгое.
- core_fingerprint.sql:хеши десяти таблиц core, включая ключи версий.
- verify_rebuild.py:повторная и отдельная чистая БД; сравниваются таблицы,все11 ответов и DQ.
- verify_resilience.py:четыре сценария обновлений,история категорий,граница интервала,новые продажи,повтор,возврат категории и отказ при backdate. Только временные копии.
- verify_customer_address.py:хеш адресов ВСЕХ старых заказов сохраняется; новый заказ получает новый адрес того же человека; main raw сравнивается до/после.
- verify_failure_guard.py:намеренный дефект обнаруживается,транзакция откатывает core; хеши постоянной истории также сохраняются.

Запускать изменяющие тесты последовательно. DATABASE_URL корректно заменяется для тестовых БД; PGDATABASE поддерживается в контейнерном режиме. Все автоматически созданные БД имеют уникальный префикс rwb_probe_ и удаляются в finally.
