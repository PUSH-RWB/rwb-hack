# BI-слой: дашборды в Apache Superset

Общий дашборд с ключевыми цифрами и десять дашбордов, по одному на вопрос кейса, поверх схемы `core`. Цвета — «дикая ягода» Wildberries
(основной `#CB11AB`, глубокий `#481173`; точное соответствие фирменной палитре не проверялось).

## Запуск

```bash
bash model/setup.sh && bash model/build.sh   # если core ещё не собрана
bash dashboard/up.sh                         # Superset + дашборды, около минуты
```

Открыть: http://127.0.0.1:8088, вход `admin` / `admin`. Порт открыт только на localhost.
Остановить: `docker compose -f dashboard/docker-compose.yml down` (добавьте `-v`, чтобы удалить и настройки).

## Один экран без прокрутки

Каждый дашборд рассчитан на окно высотой около 800 px (ноутбук). Высоты строк считает `provision.py` из весов в раскладке,
потому что Superset рисует график по высоте из раскладки, а не по размеру контейнера. Если у вас другой экран:

```bash
echo "DASHBOARD_VIEWPORT_H=950" >> dashboard/.env   # высота окна браузера в пикселях
python3 dashboard/provision.py
```

Окно выше расчётного: снизу остаётся пустое место. Ниже: появится прокрутка. Таблицы на Q5, Q7 и Q9 урезаны до топ-5 и топ-15,
чтобы помещаться в экран; полные данные есть в датасетах и в SQL Lab.

## Как устроено

- Каждый график опирается на **виртуальный датасет**: это SQL к `core`, а не копия данных. Для Q1–Q5 берётся тот же
  SQL, что в `model/answers/q0*.sql`, поэтому цифры на экране и в ответах совпадают по построению.
  Пересборка `core` дашборды не ломает: ссылок на таблицы Superset не хранит, только текст запросов.
- `provision.py` создаёт всё через REST API, это единственное место, где описаны графики. Правите там и запускаете
  `python3 dashboard/provision.py [slug]`. Объекты Capibara пересоздаются, чужие не затрагиваются.
- Тема, русский язык, формат чисел (`13 221 498,11`) и палитра: `superset_config.py`.
- К базе Superset подключается пользователем организаторов `hack` с запретом DML. Адрес задаётся в `.env`
  (`POSTGRES_HOST/PORT`), по умолчанию `host.docker.internal:5433`, как в `model/docker-compose.local.yml`.

## Допущения и ограничения

- Контрольных значений организаторов для Q6–Q10 нет. Допущения: Q6 — все статусы заказов; Q7 и Q10 — только `delivered`
  с известными датами; Q9 — заказы 2018 года по штату покупателя, все статусы; в Q10 заказ с несколькими
  отзывами попадает в несколько групп. Они записаны в примечании на каждом дашборде.
- Фильтры Superset (native filters) не настроены, дашборды показывают весь период.
- Логин `admin`/`admin` и `SECRET_KEY` из `.env` рассчитаны на локальный запуск, наружу порт не выставляйте.
